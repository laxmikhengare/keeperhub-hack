## What makes `lido-l1-bridge.json` a genuinely hard test

The contract is `OssifiableProxy` at `0x89057c7e…`; the logic lives in the implementation at
`0x7e1dbd01…` (`L1ERC20TokenBridge`), reachable only via the EIP-1967 storage slot.
The role constants live in an inherited file, `contracts/BridgingManager.sol`.

**The preimages are namespaced:**

```solidity
bytes32 public constant DEPOSITS_ENABLER_ROLE =
    keccak256("BridgingManager.DEPOSITS_ENABLER_ROLE");
```

So `keccak256("DEPOSITS_ENABLER_ROLE")` = `0x0f852be8…`, which **matches nothing**.
Brute-forcing the constant name fails. You have to read the source and hash the
*string literal*, not the identifier. This is why the deterministic pre-pass has to
extract the literal rather than guess from the name.

**There is also a decoy**: `@openzeppelin/contracts/access/AccessControl.sol` contains
`MY_ROLE = keccak256("MY_ROLE")` inside a documentation comment. It is not a role on
this contract. The extractor must not surface it.

**`callHistory` is empty on all four.** These are governance-held roles that were granted
and never exercised. That is realistic and it is the hardest classification case in the
set: a `DEPOSITS_DISABLER_ROLE` that has never fired is *not* obviously vestigial — it is
an emergency control that is supposed to sit unused. Decide this one deliberately.
